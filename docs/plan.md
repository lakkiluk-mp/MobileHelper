# Эталон — план

Тренажёр к JS-собесу. Карточка: код, прогон, короткий ответ, теория только этой задачи. Сторы не делаем. Без входа приложение работает целиком. Вход нужен только чтобы прогресс переехал на второе устройство.

## Зафиксированные решения

1. Раннер — изолированная страница (в вебе это iframe без `allow-same-origin`, позже тот же контракт в WebView). `while (true)` может подвесить страницу до таймаута ожидания — это известное ограничение. В Node CI у `vm` есть настоящий timeout.
2. `kind` — discriminated union: `predict | implement`.
3. Теория только на русском, поле `theory: string`. Английский позже — отдельное необязательное поле, текущие карточки не ломаются.
4. Прогресс анонима едет с клиентским `deviceId`. После входа записи этого устройства забираются на пользователя. Без `deviceId` прогресс не пишется.
5. Seed коммитится в репозиторий и попадает в сборку. Приложение открывает уровни без сети.
6. Приёмка прогона — golden-лента. CI гоняет код в Node и сравнивает с `expected`. Браузерный прогон использует тот же сериализатор и тот же контракт ленты.

## Пакеты

| Пакет | Что внутри | Где исполняется |
| --- | --- | --- |
| `packages/runner` | лента, сериализация логов, сравнение, хеш карточки, `HostAdapter`, Node-хост | Node в тестах. В браузерный бандл Node-хост не входит |
| `packages/shared` | zod-контракты карточки, манифеста, прогресса; `planSync` | клиент и сервер |
| `packages/content` | `cards.json`, `extra-cards.json`, `tombstones.json`, уровни | сборка и сид сервера |

Нормализация логов: аргумент — строка. Число `3`, строка `"3"` и `undefined` не совпадают. У каждого прогона свой токен, событие после закрытия окна отбрасывается.

Версия контента — не глобальный счётчик. У карточки `updatedAt` и `rev`. Хеш считается из тела. `seedVersion` — хеш всех штампов и tombstone-ов. Удаление не воскресает из seed: tombstone побеждает.

Эталон машинный, строка `answer` — для человека. Автоматика `answer` не сравнивает.

## Фазы

| Фаза | Критерий | Сейчас |
| --- | --- | --- |
| 0. Каркас и эталоны | Тест гоняет все predict-карточки. Уровни открываются без сети | Готово |
| 1. Карточки | Ответ, теория, три оценки, локальное хранилище, синк | Готово в вебе: IndexedDB вместо будущего SQLite |
| 2. Плейграунд | Тот же контракт ленты в изолированной странице. 1.1–1.21 и 5.1–5.5 совпадают с golden | Готово: iframe, не нативный WebView |
| 3. Офлайн-прогресс | Оценка → устройство → сеть → строка на сервере по `deviceId`. Плашка, если сети нет | Готово |
| 4. Вход | Привязка анонимного устройства к пользователю | Готово как вход Google/X через платформу. Нативный APK и общий keystore здесь не собираются |
| 5. Implement | Общий раннер, события `type: "test"`. Образцы `once` и `debounce`, остальные задачи — JSON | Готово: 2.4–2.6 и 6.1–6.5 |

TypeScript, живой React и LeetCode в эти фазы не входят.

## Как добавить задачу

Predict — объект в `packages/content/cards.json`. Implement — в `packages/content/extra-cards.json`. Поле `expected` у predict — лента, не пересказ. Тест `packages/runner/golden.test.ts` исполняет код и падает с фактической лентой, если эталон разошёлся. У implement тест гоняет `solution` и требует, чтобы каждое событие `test` было успешным. `answer` правится отдельно и на тест не влияет.

## Что сознательно не так, как в черновике монорепы

Отдельные `apps/mobile` (Expo) и `apps/api` появятся к сборке APK. Сейчас клиент — веб-оболочка на тех же `runner` / `shared` / `content`. Манифест, каталог и прогресс — серверные функции поверх Postgres. Схема — SQL в `migrations/`, не Drizzle.

Локальная база на устройстве в этой оболочке — IndexedDB. Контракт тот же: карточки, оценки, исходящая очередь, `deviceId`. Нативный клиент сможет заменить хранилище, не меняя ленту и синк.
